# 单车 H3 越野 RoutePlan 闭环需求规格

- **状态**：当前活动基线
- **基线日期**：2026-07-27
- **事实来源**：当前本地 `src/`、`tests/` 与
  [closed-loop-contract.md](closed-loop-contract.md)
- **范围**：单车静态 GIS 规划、候选选择、动态阻塞重规划及本地桌面/Web 交互

## 1. 功能需求

| ID | 需求 | 验收标准 |
|---|---|---|
| FR-001 | 构建车辆无关的静态 Tile | Tile 只包含 GIS/H3 静态事实、拓扑和质量信息；不同车辆复用同一 Tile，构建期不写车辆评分 |
| FR-002 | 在路由时加载车辆与物理因子配置 | 配置经严格 YAML 校验和规范化；生成车辆、因子、静态输入及拓扑哈希 |
| FR-003 | 计算物理瓶颈裕度 | 硬约束、缺失证据、坡度、锥指、沉陷和推力均产生可手算的 `safety_margin`、置信度和原因码 |
| FR-004 | 冻结有向边指标 | 每个可通行方向冻结距离、ETA、terrain risk、travel cost 和裕度区间；不可通行方向不生成 |
| FR-005 | 构建精确请求内 PortsMap | Port-pair 代价与完整有向图最短路一致；展开路径连续；超出资源上限显式失败，不近似回退 |
| FR-006 | 生成确定性多指标候选 | 使用距离、ETA、terrain risk、travel cost 四个可加目标及 widest 锚点；输出唯一且可复现 |
| FR-007 | 聚合候选与分配角色 | 输出 1～5 条路线，合并最快、最短、最大裕度、最小代价和经扰动验证的独立备选角色 |
| FR-008 | 持久化 RoutePlan 并显式选择 | 首次规划不自动激活；计划、GIS 图层及 manifest 可往返；重复选择幂等，版本冲突拒绝 |
| FR-009 | 管理动态阻塞生命周期 | 控制层管理 tentative、confirmed、cleared、expired；低层规划器仅接收解析后的阻塞单元集合 |
| FR-010 | 执行状态化 D* Lite 重规划 | 基础图只读；局部修复复用状态；失败时按同一任务偏好有界全局回退或进入安全保持/失效状态 |
| FR-011 | 提供一致的 CLI、HTTP 和桌面入口 | 所有入口调用同一业务适配器；桌面生产后台链使用普通线程、单向队列和 UI 定时器 |
| FR-012 | 加载私有在线底图配置 | 显式路径、环境配置路径、项目私有 YAML 依次选取；非空环境 token 覆盖 YAML；无 token 仍可本地运行 |
| FR-013 | 加载多矢量地物覆盖与空间物理属性 | 支持目录式多 Shapefile 自动合并载入与标准化代码解析，透传 depth 与 rowspacing 物理属性 |
| FR-014 | 高精度父格网res11+子格网res14建网与规划 | 默认采用父格网 res11 与子格网 res14，提供亚米级空间分辨率，支持紧凑测试区建模 |

## 2. 强约束

| ID | 约束 | 验收标准 |
|---|---|---|
| NFR-001 | 确定性 | 相同规范输入产生相同计划 ID、候选 ID、角色、排序和规范 JSON |
| NFR-002 | 输入零信任 | 公共边界拒绝布尔伪数值、非有限数、未知字段、空路径、非法状态和越界资源参数 |
| NFR-003 | 物理可解释性 | 内部规划只使用物理裕度和冻结边指标；不以主观权重合成通行性排序 |
| NFR-004 | 状态安全 | JSON 使用同目录临时文件原子替换；写失败保留旧状态；损坏状态隔离后显式报错 |
| NFR-005 | 解耦 | 核心依赖为单向 DAG；Tile 不依赖车辆；协调模块只保留 Protocol 和基础模型 |
| NFR-006 | 凭据安全 | 实际地图 token 不得进入受跟踪源码、示例、日志、测试快照或成果文件 |
| NFR-007 | 质量门禁 | 全量测试通过；语句覆盖率不低于 80%，分支覆盖率不低于 70%；ruff、mypy、差异检查通过 |
| NFR-008 | 兼容边界 | Legacy standalone evaluator、旧图适配器和 Qt compatibility shim 可保留，但不得进入生产闭环 |

## 3. 状态机

阻塞状态：

```text
tentative -> confirmed -> cleared
                       -> expired
```

路线状态：

```text
active -> safe_hold
       -> superseded
       -> invalidated
```

所有状态变化必须有明确输入、时间和持久化版本；不得猜测当前位置、活动候选或阻塞时间。

## 4. 非目标

本基线不实现遗传式多目标优化、多车冲突树求解、实时交通、大规模并行 Tile、磁盘
PortsMap、在线服务部署或自动化浏览器 UI。相关旧 MVP 文档只用于解释迁移历史，不构成
当前需求。
