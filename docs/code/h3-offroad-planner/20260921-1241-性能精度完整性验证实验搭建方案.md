## 5. 处理组设计

### 5.1 分支性能组

| 组 | 提交 | 配置 | 用途 |
| --- | --- | --- | --- |
| B0 | `3fbff57` | 原生配置 | fast-five 分支真实基线 |
| C0 | `5e0b9cc` | 当前默认配置 | 当前性能与质量 |
| C1 | `5e0b9cc` | 禁用离线端口对，强制在线端口搜索 | 衡量离线端口表总收益与路线差异 |
| C2 | `5e0b9cc` | 使用离线正命中，但禁用负向旁路 | 单独量化负向旁路收益和假阴性 |
| C3 | `5e0b9cc` | `MAX_BOUNDARY_PORTS=8/16/32/不限` | 测量端口截断的性能—完整性曲线 |
| C4 | `5e0b9cc` | fast-five 开/关，环境压力固定 | 测量候选广度和环境路线召回 |
| C5 | `5e0b9cc` | targeted repair 与完整 2-ring 对照 | 测量局部修补的最优性和多样性差距 |
| C6 | `5e0b9cc` | `require_independent_backup=true` | 检查“成功返回”是否满足完整交付语义 |

最小实现方式：增加一个实验 runner 和少量仅供 runner 注入的显式参数。不要新建 benchmark 框架、服务层或插件系统。所有非默认开关必须写入运行 manifest，且生产默认行为不能被实验脚本静默改变。

### 5.2 Oracle 组

建立两级 oracle，避免直接对所有 15 万细格做无法承受的全排列：

- **O1 父格级 oracle**：对每个选中父格枚举全部真实边界端口，逐 source 运行在线 `_fine_tile_search()`；用于确认端口对可达性和最短成本。
- **O2 路线级 oracle**：在固定 OD 上关闭离线表、负向旁路和端口截断，使用足够宽的走廊；用于比较最终路径和目标值。

O1 是 P-01/P-02 的主要判定依据；O2 只需覆盖固定回归路线和定向反例，不要求作为日常性能基准。

## 6. 五组实验

### E1：数值等价与非法值防护

**目的**：验证向量化、坡度反对称和 `_fast_create` 没有改变同一输入上的物理结果。

步骤：

1. 从真实索引分层抽样节点和有向边：正常值、阈值附近、零坡度、正反坡、低置信度和极端土壤参数。
2. 对同一批输入分别调用标量实现和向量化实现。
3. 比较所有数值字段、布尔通行判定、reason codes 和正反方向结果。
4. 注入 NaN、无穷大、负速度、逆序区间和置信度越界，确认批量入口在进入 `_fast_create` 前拒绝非法数据。

判定：

- 有限浮点字段最大绝对误差 `<=1e-6`；
- `is_passable`、reason codes、空值语义必须完全一致；
- 非法值不得静默进入候选搜索；
- 任一离散判定不一致即失败，不能用平均误差掩盖。

### E2：端口截断与负向旁路完整性

**目的**：直接寻找“优化结果无记录，但在线搜索可达”的假阴性。

对每个定向父格执行：

1. 枚举全部真实跨父格边界端口，记为 `P_all`。
2. 记录当前八端口集合 `P_8`，计算 `P_all - P_8`。
3. 对 `P_all` 中每个 source 运行 O1，得到真实可达 target 与最短成本。
4. 分别运行 C1、C2、C3，记录每个 source-target 的存在性和成本。
5. 特别统计当前负向旁路返回空集合、但 O1 找到路径的情况。

核心指标：

```text
port_recall = optimized_reachable_pairs / oracle_reachable_pairs
false_negative_count = |oracle_reachable - optimized_reachable|
pair_cost_gap = (optimized_cost - oracle_cost) / oracle_cost
```

判定：

- 假不可达数量必须为 0；
- 同一端口对路径重新评价后的成本误差 `<=1e-6`；
- 如果端口上限导致 recall 小于 100%，必须把当前算法定性为近似搜索，并给出业务可接受阈值，不能继续宣称全局等价。

### E3：路线级最优性、环境鲁棒性和走廊范围

**目的**：确认受限宏观图是否漏掉更优路线。

每个 OD 运行 C0、C1、C2、C3、C4、C5 和 O2。所有返回路径用同一个当前 evaluator 重新计算，禁止直接比较各版本写出的旧 cost。

按角色比较：

- 最快 ETA；
- 最短距离；
- 最大通行裕度；
- 最小 travel cost；
- 独立备份；
- 固定环境压力下的鲁棒路线。

指标：

```text
objective_gap(role) = (current_value - oracle_value) / abs(oracle_value)
path_overlap = |cells_current ∩ cells_oracle| / |cells_current ∪ cells_oracle|
candidate_recall = oracle_nondominated_matched / oracle_nondominated_total
```

同时记录路径连续性、阻断格命中、几何有效性、角色集合、父格重叠和独立性。

判定分两层：

- **等价声明门槛**：每个纯目标角色 gap 为 0（容许 `1e-6` 数值误差）、无可达性差异。
- **近似算法验收门槛**：如允许非零 gap，阈值必须由业务方事先书面确定；实验报告只呈现分布，不事后根据结果放宽阈值。

### E4：离线资产身份与缓存失效

**目的**：确认过期离线端口表不会被接受。

基于同一小型索引依次只改变一个因素：

1. 车辆参数；
2. 一个 cell 的静态物理字段但保持 cell 数不变；
3. 一条 edge 的坡度或距离但保持 edge 数不变；
4. factor model 参数；
5. 端口上限或端口选择算法版本；
6. port-pair schema 版本。

每次尝试加载旧端口对，记录是否拒绝、是否回退在线搜索以及告警内容。

验收目标：离线资产 manifest 至少同时绑定并验证：

- `vehicle_hash`
- `static_input_hash`
- `graph_topology_hash`
- `factor_model_hash`
- `port_selection_hash`
- `port_pairs_schema_version`

任一身份变化都必须拒绝旧资产或显式回退，不能继续进入负向旁路。

另外执行“内容变化、数量不变”的图突变测试，确认 `static_input_hash()` 和 `graph_topology_hash()` 不会返回过期缓存。

### E5：隔离性能基准

**目的**：建立可信的分支性能和优化贡献数据。

定义两类指标：

- **process-cold**：每条路线由全新 Python 进程执行；无进程内 cache，但允许操作系统文件缓存。
- **process-warm**：同一进程先预热一次，再测 5 次。

不要把 process-cold 称为磁盘冷启动；Windows 文件缓存没有被可靠清空时，应如实标注。

执行规则：

1. 每个分支、处理组、OD 至少 1 次预热和 5 次正式测量。
2. B0/C0 的 process-cold 每次必须启动独立 Python 进程。
3. 处理组顺序随机化，避免温度、系统负载和文件缓存总是偏向后运行的组。
4. 每次使用唯一输出目录；不使用 `skip_if_done`，不读取前一次结果作为完成依据。
5. 运行期间记录 CPU、RSS、磁盘读取量和输出字节数。
6. 报告 median、P95、最小值、最大值和全部原始样本，不只报告最快一次。

必须采集的阶段指标：

- `index_open_s`
- `coarse_search_s`
- `corridor_load_s`
- `graph_build_s`
- `factor_eval_s`
- `reachability_s`
- `candidate_search_s`
- `geometry_s`
- `plan_ready_s`
- `fine_search_calls`
- `offline_pair_hits`
- `base_pair_cache_hits/misses/entries`
- cell、edge、active parent、repaired parent 数量

## 7. 实验 runner 的最小结构

只新增一个 runner，例如 `scripts/benchmark_precision_ab.py`，负责：

1. 读取一份静态 JSON/YAML 实验矩阵；
2. 每个 process-cold case 启动一个子进程；
3. 写入不可变的 `experiment_manifest.json`；
4. 复制而不是改写原始 `performance.json` 和 `route_plan.json`；
5. 汇总为 JSON/CSV，不在 runner 内做复杂绘图或建立新框架。

建议目录：

```text
outputs/precision_performance_ab/<experiment_id>/
├── experiment_manifest.json
├── cases.json
├── raw/
│   └── <commit>/<treatment>/<route>/<run_id>/
│       ├── invocation.json
│       ├── performance.json
│       ├── route_plan.json
│       ├── stdout.log
│       └── stderr.log
├── comparisons/
│   ├── numeric_equivalence.json
│   ├── port_pair_recall.json
│   ├── route_quality.json
│   ├── asset_identity.json
│   └── performance_samples.csv
└── summary.md
```

`experiment_manifest.json` 至少包含：

- commit、branch、worktree、dirty 状态；
- Python 与模块绝对路径；
- 输入文件路径和 SHA-256；
- 环境快照 hash；
- 全部处理开关；
- 启动时间、机器信息和随机化 seed。

## 8. 结果判定矩阵

| 结论 | 必须同时满足 |
| --- | --- |
| 数值等价 | E1 全字段容差通过，离散判定完全一致，非法值不静默进入 |
| 端口搜索完整 | E2 假阴性为 0，port recall 100% |
| 完整搜索等价 | E2 完整，且 E3 各纯目标角色对 O2 的 gap 为 0 |
| 离线资产安全 | E4 所有身份变化均拒绝旧资产或显式回退 |
| 五角色完整交付 | 四个核心角色和独立备份均存在，且相应路径连续、物理和几何有效 |
| 30 秒冷性能成立 | C0 的 2km process-cold P95 不超过 30 秒；当前 30.78 秒单次顺序结果不满足该声明 |
| 可接受近似 | 非零 gap、候选漏召回和独立性损失均低于事先确定的业务阈值 |

任何性能结果都必须与同一次运行的质量结果绑定。若 `plan_ready_s` 达标但出现以下任一情况，应报告为“性能通过、质量失败”：

- 假不可达；
- 目标值超出阈值；
- 路径不连续或命中阻断格；
- 没有几何有效候选；
- 缺失要求的独立备份；
- 离线资产身份不匹配。

## 9. 建议执行顺序

按最小成本优先：

1. **E1 数值等价**：先确认向量化没有直接数值回退。
2. **E2 父格级完整性**：最快发现八端口和负向旁路是否会漏路；这是最高优先级。
3. **E4 资产身份**：避免用过期缓存污染后续路线实验。
4. **E3 路线级质量**：在固定 OD 和定向反例上跑昂贵 oracle。
5. **E5 性能基准**：最后对已经证明质量合格的处理组统计耗时。

若 E2 已发现假阴性，不必先跑完整性能矩阵；应先把当前算法标记为近似搜索，再决定修复还是制定明确的质量损失阈值。

## 10. 最终交付物

实验完成后应交付：

1. 原始不可变运行产物和 manifest；
2. 每项优化的耗时贡献表，而不是混合基线的单一倍数；
3. 数值字段最大误差和离散判定差异；
4. 端口对 recall、假阴性清单和成本 gap；
5. 按路线角色统计的目标 gap、路径重叠、几何有效性和独立性；
6. process-cold 与 process-warm 分开的 median/P95；
7. 明确结论：等价优化、可接受近似、不可接受回退或证据不足。

在这些交付物齐全前，当前最稳妥的对外表述是：**已观测到显著性能提升；向量化未见数值降精度证据；搜索完整性和路线交付等价性仍待专项 A/B 验证。**
