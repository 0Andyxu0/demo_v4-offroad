三、文档遗漏的问题
N-01（最关键）：负向旁路有一条明确的触发路径，不只是假设风险。 预计算端口由 offline_pairs.py:424-443 的 _extract_parent_ports 几何推导，并要求 neighbor_parent in known_parents（:438，known_parents 取自索引 coarse 边表）；运行期端口由 directed_edges 推导。二者不同源。当定向走廊修补新增的父格 B 不在 known_parents 中时，B 的邻居格 c 不会进入已覆盖父格 A 的预计算端口集，但 c 是 A 的运行期端口 → (profile, A, c) 查不到 → 而 (objective, A) 已在 _offline_parents_by_profile → base_pairs=() → c 被静默孤立。触发者正是 P-06，而本次 2km 恰好加了 10 个父格。这把 P-02 从"离线表可能不完整"的假设，升级为有具体触发链的缺陷，应进 P0 并优先做定向复现。

N-02：负向结果会被写入进程级全局缓存（portsmap.py:667/713 把 () 一并 _base_pair_cache_put），在同一 base_cache_identity 下跨请求存活、不自愈。
