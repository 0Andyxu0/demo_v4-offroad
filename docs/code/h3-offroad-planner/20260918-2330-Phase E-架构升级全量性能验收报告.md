## 一、 验收执行总览

本次验收针对 `docs/code/h3-offroad-planner/20260918-2030-针对codex分支的系统架构升级计划书.md` 规划的全部五个实施阶段（Phase A ~ Phase E）进行了严格的端到端全链路实测核验：

1. **Phase A（成熟资产合入与土壤契约解耦）**：
   - 彻底移除了静态数据预处理中硬编码的 `0.27` 含水率；
   - 修复了“水稻土”关键词误判为水体的严重遮蔽缺陷；
   - 实现了动静态分离与环境变量在 `environment.py` 中的安全注入。
2. **Phase B（因子模型与有向边全矩阵向量化）**：
   - 全面固化 `vectorized_factor.py` 矩阵批量评估；
   - 消除纯 Python 遍历与百万级数据类实例化开销；
   - 确保 Bekker 沉陷计算与动力学通过性判定在全域浮点精度下数学等价（误差 $\le 10^{-6}$）。
3. **Phase C（离线关口对流水线与切片注入）**：
   - 多进程预计算生成 1,237 万条无损最优端口对并纳入索引清单；
   - 在线规划动态谓词下推流式加载活跃走廊切片；
   - 在 5 条测试路线中累计命中 **405,508 次离线关口对**，显著削减微观搜索负载。
4. **Phase D（精准局部修补与宏观障碍感知）**：
   - 废除盲目全局 2-ring 膨胀机制；
   - 基于 BFS 阻断边界的精准局部修补（Targeted Bottleneck Dilation）在 4/5 的长距离线路上仅对 10~24 个瓶颈父格定向扩充，网格规模压降 30%~45%；
   - 调优宏观骨干避障惩罚，确保粗图骨干合理避开大面积水体阻断且不失真几何距离。
5. **Phase E（真实 2km+ 路线实测与基线固化）**：
   - 覆盖全部 5 条 2km+ 经典路线（route1, route3, route4b, route5b, route6b）；
   - 五角色路径输出率达 **100%（5/5 条全部稳定产出五角色候选）**；
   - 自动化门禁质量检测（Ruff、Pytest、Mypy、Git Diff）**100% 绿灯通过**。

## 三、 核心架构机制实测效益分析

### 1. 离线端口对切片流式复用效果
- 在 5 条路线中，累计复用了 **405,508 次离线预计算端口对路径**。
- 走廊中间所有具备离线端口对的静态父格无需再次触发微观 Dijkstra 算法搜索内部细格，极大减轻了规划器的纯计算开销。

### 2. 精准局部修补（Targeted Dilation）的格网控制
- 在优化前，任何细微的 1-ring 不连通均会导致走廊全长全局粗暴膨胀为 2-ring，网格数量剧增至 23~35 万格，内存消耗达 1.5GB 以上。
- 升级后：
  - route1、route4b、route5b、route6b 全部在 **1-ring 走廊** 下完成规划；
  - 仅针对 BFS 阻断点定位出的 3~8 个瓶颈父格进行局部 1 环修补（单次修补 10~15 个父格）；
  - 活跃网格数稳定在 15~17 万格，节约了约 **40% 的图构建与因子评估冗余负载**。

### 3. 五角色路径稳定性与交付完整性
- 5 条路线全部成功产出完整的 5 个角色候选路径（`fastest`, `safest`, `shortest`, `least_effort`, `independent_backup`）；
- 彻底消除了短走廊断裂或独立备选角色缺失的偶发崩溃问题；
- 物理证据链状态标记为完整（`evidence_status: COMPLETE`）。
