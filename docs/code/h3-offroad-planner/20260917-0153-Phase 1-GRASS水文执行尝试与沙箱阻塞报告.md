> 时间：2026-09-17 01:53
> 分支：fix/independent-backup-and-sampling
> 状态：代码问题已修复，GRASS 仍受沙箱目录权限阻塞

## 1. 目标

使用已下载的 Copernicus 30m DEM 执行 GRASS r.watershed，生成上游完整水文基线。

## 2. 已完成修复

### 2.1 GRASS 输出编码

- 原问题：GBK 解码 GRASS 输出时崩溃；
- 修复：subprocess 使用 UTF-8 编码和 errors=replace。

### 2.2 临时目录清理

- 原问题：TemporaryDirectory 清理时因沙箱权限抛 WinError 5；
- 修复：改用 tempfile.mkdtemp，不再自动清理，避免清理错误中断流程。

### 2.3 GRASS 环境变量

- 设置 GRASS_CONFIG_DIR 到输出目录下的 .grass_config；
- 设置 HOME 和 USERPROFILE 到输出目录下的 .grass_home；
- 设置 TEMP/TMP/TMPDIR 到输出目录下的 .grass_tmp。

## 4. 当前阻塞

GRASS 启动时创建临时会话目录失败：

```text
PermissionError: [Errno 13] Permission denied:
...\.grass_tmp\grass8-31287-xxxxx\gisrc
```

根因：

- GRASS 使用 `Path.mkdir(mode=0o700)` 创建临时目录；
- 当前沙箱中，以 mode=0o700 创建的目录会立即失去当前用户的写入权限；
- 因此 GRASS 无法在临时目录中写入 gisrc，启动失败。

这不是项目代码错误，而是沙箱对 POSIX mode 的 Windows 映射问题。

## 5. 建议解决方式

1. 在正常 Windows 环境或 CI 中运行 GRASS 水文重建；
2. 或修改本机 GRASS 的 grass85.py，将 mkdir mode 改为 0o777 或使用 exist_ok；
3. 或由管理员预先创建 GRASS 临时目录并放开权限。
