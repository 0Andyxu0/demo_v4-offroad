# 当前覆盖率门禁说明

> 状态：活动门禁说明，2026-07-27。覆盖率是回归安全网，不替代物理手算、完整图最短路、
> 状态转移或确定性 Oracle。

## 1. 阈值

| 指标 | 最低值 | 计算方式 |
|---|---:|---|
| 语句覆盖率 | 80% | `covered_lines / num_statements × 100` |
| 分支覆盖率 | 70% | `covered_branches / num_branches × 100` |

两个指标必须分别计算、分别通过。不得使用 pytest-cov 的单一总百分比代替分支阈值，也不得
通过排除核心算法文件来提高结果。

## 2. 执行方式

```powershell
$env:PYTHONIOENCODING = "utf-8"
python scripts\verify_baseline.py
```

脚本在被 Git 忽略的 `pytest_temp_baseline_gate/coverage.json` 中生成机器证据，读取
coverage JSON 的原始计数并独立计算语句和分支比例。普通 `pytest` 配置不自动增加覆盖率
开销。

## 3. 当前关注点

- 桌面原生文件对话框、WebEngine 和消息框仍主要依靠 offscreen 替身；生产后台线程和队列
  合同已有专门测试。
- GIS/GPKG 测试依赖本地二进制包环境，门禁失败时必须区分环境缺失和真实回归。
- CL-001～CL-040 是强合同测试；其他历史 T-* 或白盒覆盖测试不计入合同追踪分母。
- 每次基线验收使用实时输出，不在本文维护会迅速过期的固定测试数量。

## 4. 最近快照

2026-07-27 本地执行结果：326 项测试通过，语句覆盖率 85.46%，分支覆盖率 71.66%。
该数字只记录本次基线验收；后续判断必须重新执行脚本。

## 5. 失败处理

- 测试失败：先修复对应合同或实现，不降低阈值。
- 语句或分支不足：增加针对未覆盖行为的白盒测试，不删除合同测试。
- 环境依赖失败：报告缺失依赖和命令，修复环境后重跑，不伪造 PASS。
- 覆盖率 JSON 损坏或字段缺失：门禁脚本失败关闭，不使用上次结果。
